Why This Exists

OpenFin의 운영 목적

OpenFin은 금융·세금 데이터를 보여주는 소개 페이지가 아니라, 앱과 AI가 같은 기준을 읽도록 만드는 온톨로지 표면입니다.

기존 금융 정보의 문제

  • 세금·복지·카드·은행·보험 정보가 기관·파일별로 흩어집니다.
  • 상품명·우대조건·한도·기준일이 바뀌어 공통 기준이 필요합니다.
  • 원문 출처·수집일이 없으면 답변을 검증하기 어렵습니다.

OpenFin에 반영한 방식

  • manifest·샤드 인덱스로 도메인별 항목·상품 수를 노출합니다.
  • 각 노드에 ID·타입·설명·조건·출처·이웃 노드를 보존합니다.
  • Pages 탐색기와 Cloudflare MCP가 같은 export를 읽습니다.

ChatGPT Connector

ChatGPT에 OpenFin MCP 연결하기

OpenFin MCP는 읽기 전용 서버입니다. ChatGPT의 Plugins에서 아래 MCP URL을 추가하면 세금, 지원금, 카드, 은행, 보험 온톨로지를 ChatGPT 대화 안에서 검색하고, 조건에 맞는 비교·추천 후보와 다음 행동을 확인할 수 있습니다.

붙여 넣을 MCP 서버 URL

읽기 전용 도구를 제공합니다: `exports`, `search`, `fetch`, `discover`, `compare`, `recommend`.

  1. ChatGPT 설정 열기 Settings → Plugins → Advanced에서 Developer mode를 켭니다.
  2. 원격 MCP 서버 추가 Plugins 탭에서 새 MCP 서버를 추가하고 위 URL을 입력합니다.
  3. 대화에서 커넥터 선택 질문할 때 OpenFin 커넥터를 선택하고 “청년 월세 지원”, “체크카드 전월실적”, “신용대출 금리”처럼 검색합니다.

exports

OpenFin이 현재 읽는 export, 샤드 manifest, 기준일, 총 항목 수를 확인합니다.

search

사용자 질문과 의도를 기준으로 세금, 지원금, 카드, 은행, 보험 노드를 찾습니다.

fetch

선택한 노드의 기준, 출처, 상품 메타데이터, 연결 노드를 자세히 조회합니다.

discover / compare

상품 후보를 구조화하고 예금·적금·대출의 비교 가능 필드를 기준으로 비교합니다.

recommend

필수 프로필·제약조건과 검증 상태를 확인한 뒤, 근거가 부족한 상품은 추천에서 제외합니다.

Content Additions

현재 반영된 추천형 금융 표면

현재 데이터와 운영 게이트를 기준으로 웹 탐색기와 MCP에서 확인할 수 있는 기능 상태입니다.

검색·탐색

질의를 의도와 분야로 해석해 세금·지원금·카드·은행·보험 후보를 찾고, 종료·미확인 항목은 기본 결과에서 분리합니다.

반영: search · discover · status-aware filtering · 샤드 hydration

상품 비교

예금·적금·대출은 기간, 금리, 한도, 상환 등 비교 필드를 구조화하고 검증된 비교 후보만 비교 결과에 사용합니다.

반영: compare · comparison completeness · sales verification evidence

추천 안전 게이트

추천은 프로필·제약조건·판매상태·필수 필드·검증 증거를 모두 확인하며, 현재 공개 추천이 차단된 도메인은 후보 설명만 제공합니다.

반영: recommend · reference_only 제외 · fail-closed recommendation policy

지원사업 필드화

지역, 대상, 신청기간, 상태, 제외 요약을 필드로 유지해 “내가 신청할 수 있는 지원”을 설명할 수 있게 했습니다.

반영: support search · region/youth intent · excluded_summary

공식 보험 출처

보험 공시와 공식 문서에서 확인된 보장·가입·보험료 필드를 반영하고, 공개되지 않은 대기·감액 정보는 unknown으로 보존합니다.

반영: official disclosure overlay · source checksum · unknown fail-closed

샤드 인덱스

대용량 검색 인덱스는 manifest와 도메인 샤드로 나누고, 화면과 MCP가 같은 공통 데이터 계약으로 hydrate합니다.

반영: 21,251 items · shard item_count 검증 · inline/shard loader

검증 표면

로컬 릴리스 검증과 실제 MCP smoke/regression 결과를 함께 기록해 화면에 표시되는 데이터 계약을 추적할 수 있습니다.

반영: release 20/20 · live regression 37/37 · smoke 11/11
